# /honey — 꿀퀴즈 하루치 반영

리더님이 claude.ai 540 프로젝트에서 지은 하루치 블록을 받아 배포까지 처리한다.

## 입력

`$ARGUMENTS` 또는 이어지는 메시지로 하루치 문항이 온다. JSON 형태이거나 예전 JS 블록 형태일 수 있다.
블록이 없으면 붙여넣어 달라고 요청하고 멈춘다. **문항을 지어내지 않는다.**

## 실행 순서

### 0. 최신 상태 맞추기

```bash
git pull
```

리더님이 GitHub 웹에서 직접 고쳤거나 다른 기기에서 작업했을 수 있다. 항상 먼저 당겨온다.

### 1. 접수 확인
- 날짜를 읽는다.
- `days/{날짜}.json` 이 이미 있으면 **덮어쓰지 말고** 리더님께 확인한다.
- 문항 수와 본문 범위를 한 줄로 확인 보고한다.

### 2. 파일 생성

`days/YYYY-MM-DD.json` 을 만든다. 구조는 이렇다.

```json
{
  "date": "2026-09-09",
  "passage": "창세기 25–27장, 마태복음 9장",
  "memory": { "text": "...", "cite": "...", "closing": "..." },
  "quiz": [
    {
      "ref": "창세기 25장",
      "q": "...",
      "opts": ["...", "...", "..."],
      "a": 1,
      "hintRef": "창세기 25:23",
      "hintText": "(개역개정 전문)",
      "note": "(해설, 절 표기 포함)"
    }
  ]
}
```

- `date` 는 파일명과 반드시 같아야 한다.
- `a` 는 정답이 `opts` 에서 몇 번째인지(0부터). 보기 순서는 화면에서 매번 섞이므로 **정답 위치를 조정하지 않는다.**

### 3. 목록 갱신

`days/index.json` 의 `days` 배열 맨 앞에 한 줄을 추가한다. 최신 날짜가 위.

```json
{ "days": [
  { "date": "2026-09-09", "passage": "창세기 25–27장, 마태복음 9장" },
  { "date": "2026-09-08", "passage": "창세기 22–24장, 마태복음 8장" }
] }
```

`passage` 는 날짜 파일의 것과 **글자 하나까지 같아야 한다.**

**`index.html` 은 수정하지 않는다.** 문항 추가로 화면 코드가 바뀔 일은 없다.

### 4. 검증 (건너뛰지 말 것)

```bash
node verify.mjs
```

- 오류가 나오면 **되돌리고** 원인을 보고한다. 임의로 문항 내용을 고쳐 통과시키지 않는다.
- 경고만 나오면 그대로 보고하고 다음으로 간다.

### 5. 보고 및 승인 요청

> 검증 통과했습니다. 등록된 날짜 N일, 최신은 YYYY-MM-DD 10문항.
> 경고 N건: (있으면 나열)
> 올릴까요?

**승인 없이 올리지 않는다.**

### 6. 배포

```bash
git add -A
git commit -m "add YYYY-MM-DD 창세기 N–M장, 마태복음 N장"
git push
```

GitHub Pages가 30초~1분 안에 반영한다. 완료되면 주소와 함께 한 줄로 보고하고, 폰에서 한 번 열어보시라고 안내한다.

```
https://karamjang-arch.github.io/honeybible/
```

## 이미 올린 날짜를 고칠 때

배포 비용이 0이므로 오타 하나도 바로 고쳐 올린다. 다음 날까지 미루지 않는다.

리더님이 "9월 3일 5번 해설을 이렇게 바꿔줘" 같이 요청하면:

1. `git pull`
2. `days/{날짜}.json` 에서 **해당 항목만** 고친다. 다른 문항은 건드리지 않는다.
3. `passage` 를 바꿨다면 `days/index.json` 의 같은 날짜도 함께 고친다. 둘은 항상 같아야 한다.
4. `node verify.mjs`
5. 승인 요청 후 `git commit -m "fix YYYY-MM-DD N번 해설"` → `git push`

**개역개정 본문(hintText, memory.text)은 리더님이 명시적으로 지시한 경우에만 고친다.** 스스로 판단해서 고치지 않는다.

## 로컬 미리보기

`index.html` 을 더블클릭하면 브라우저 보안 정책 때문에 `days/` 를 읽지 못한다. 확인이 필요하면 간이 서버를 띄운다.

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

**확인이 끝나면 터미널에서 Ctrl+C 로 서버를 끄고, 브라우저 탭도 닫는다.**
서버가 꺼진 뒤에도 탭이 열려 있으면 첫 화면은 남아 있지만 지난 날짜를 누를 때 "불러오지 못했습니다" 가 뜬다. 파일 문제가 아니라 서버가 없는 것이므로, 이 증상이 보고되면 먼저 주소창을 확인한다.

## 지켜야 할 것

- 개역개정 본문(`hintText`, `memory.text`)은 한 글자도 수정하지 않는다. 오류가 의심되면 고치지 말고 보고한다.
- 문항의 신학적 판단은 리더님 몫이다. CC는 형식과 안전만 책임진다.
- 검증 실패 상태로는 어떤 경우에도 올리지 않는다.
- 미래 날짜 파일을 미리 올려도 화면에서는 그날이 되어야 열린다. 미리 만들어 두는 것은 괜찮다.
